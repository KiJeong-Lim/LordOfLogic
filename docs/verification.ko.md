# LoL 릴리스 검사

정교화기와 전술이 완성한 항을 별도 Hol 세션의 커널이 검사한다. 판정은
커널 규칙, Haskell의 엄격 양성과 가드 오라클, 프레스버거 결정 절차,
항·환경의 번역과 Hol 컴파일러 및 실행기에 의존한다. C 가상 기계의 GC,
단일화기와 FFI도 여기에 속한다. 커널의 절 순서와 cut, 단일화의 실행
의미가 바뀌면 같은 규칙의 판정도 달라질 수 있다. 명시적으로 선언한
`Axiom`은 가정이다. 전달받은 객체는 `lol --check-only FILE.lolo`로
검사한 뒤 정리별 가정을 살핀다. 검사 대상 모듈 전체에 선언된 공리가
없어야 한다면 `lol --check-only --no-axioms FILE.lolo`를 실행한다.

독립 저장소에서 `cabal test release-examples`는 검사기를 빌드하고 모든
예제의 종료 코드·표준 출력·표준 오류를 기록된 기대값과 대조한다. 검사기는
리눅스의 `/proc`에서 자식 프로세스 전체의 RSS를 읽는다. 양성
예제에는 완성된 증명이 있다. 음성 예제는 타입 변환, 제거, 엄격 양성,
가드 조건과 전술 실패를 다룬다. 별도의 예제는 정상적인 구조적 재귀와
중첩 양성 귀납형을 선언하고 닫힌 계산 정리의 가정이 없는지 확인한다.

리눅스에서 저장소 루트를 열고 다음 두 명령으로 릴리스 검사를 직접 실행한다.

```sh
python3 ci/lol-release.py proofs
python3 ci/lol-release.py sanitizers
```

`proofs`에는 GHC, Cabal, Python 3, Node와 Rocq 9.2.0이 필요하다.
`ROCQ`로 실행 파일을 지정할 수 있다. 기준 opam switch는
`rocq-core.9.2.0`과 `rocq-stdlib.9.1.0`을 사용한다. 편집기 프로토콜과
V1 언어 검사가 끝나면 표준 라이브러리와 모든 양성 예제를 새 디렉터리에
내보낸다. 이어서 모든 모듈을 의존 순서대로 `rocq compile -noinit`으로
컴파일한다. 이 독립 검사가 보이는 것은 검사한 선언을 Rocq 커널도
받는다는 점이다. 명시적인 공리를 전제로 한 정리는 양쪽에서 수락될 수 있다.

`sanitizers`는 `filepath < 1.5`를 지정해 지원하는 1.4 API를 검사한다.
`-fsanitizers`로 빌드한 실행 파일이 ASan과 UBSan을
로드하는지 확인한다. 컴파일한 Hol 초기화 캐시는 끈 상태로 모든 양성
예제의 출력과 계산 정리를 검사한다. GHC 런타임 때문에 leak 검사는
끄며, 해당 입력이 실제 실행한 경로의 메모리 오류와 정의되지 않은 동작
진단을 확인한다. 두 작업 모두 시간과 프로세스 트리 RSS를 제한한다.

V1은 `Section`, `Context`, `End`를 지원한다. sort는 `Prop`, `Set`과
서술적 `Type` 계층이다. coinductive 선언·cofixpoint·엄격 명제 sort
`SProp`의 타이핑은 구현되지 않았다. 증명을 생략하는 `Admitted` 명령이나
우주 검사를 끄는 옵션은 없다.

상시 회귀에는 정상적인 중첩 양성 귀납형, 직접 부분트리에 대한 재귀와
계산 결과의 변환, 의존 레코드, 비서술적 명제로부터의 제거 경계가 들어
있다. 전역 `map`에 재귀 함수를 넘기는 트리 크기 계산, `eq_refl`에서의
의존 transport와 합동 증명의 계산, 같은 매개변수에서의 구조적 상호
재귀까지 여섯 닫힌 정리의 가정을 검사한다. 과거 각 가드 검사 이슈를 일대일로 재현하는
목록까지 갖추지는 않았다. 여기 적은 결과는 등록된 프로그램의 판정이다.
이 릴리스 검사에서 감사 보고서의 과거 공개 재현 결과를 별도로 다시 얻은 것은 아니다.
