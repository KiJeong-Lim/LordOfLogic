## 표기 스코프와 custom entry

`cabal run -v0 lol -- example/V1Scopes.lol`을 실행하면 같은 식이 왼쪽
스코프에서는 `red`, 오른쪽에서는 `blue`로 계산된다. 이어서 두 함수의
일반화된 타입을 검색하고, 편집기에서 한 단계씩 실행할 수 있는 증명을
검사한다.

한 스코프 안에 여러 기호의 해석을 모을 수 있다. 아래 선언에서
`Open Scope calc_scope.` 이후에는 `seed ⊕ seed`가 `mix seed seed`를 뜻한다.
스코프를 닫은 뒤에는 `%calc`로 그 식에만 해석을 지정한다.

```coq
Declare Scope calc_scope.
Delimit Scope calc_scope with calc.
Infix "⊕" := mix (at level 50, left associativity) : calc_scope.
Open Scope calc_scope.
Definition doubled : Item := seed ⊕ seed.
Close Scope calc_scope.
Definition explicit_scope : Item := (seed ⊕ seed)%calc.
```

custom entry는 별도의 항 문법이다. 다음 선언에서 `<{ ... }>`의 내부는
expression 문법을 쓴다. 그 문법에서만 `atom`과 `+`가 이 의미를 갖는다.

```coq
Declare Custom Entry expression.
Notation "<{ x }>" := x (x custom expression).
Notation "'atom'" := seed (in custom expression at level 0).
Notation "x + y" := (mix x y) (in custom expression at level 50, left associativity).
Check <{atom + atom}>.
```

인수에 `x constr`를 쓰면 그 인수를 기본 항 문법으로 읽는다. `x custom
entry at level 50`은 인수의 문법과 읽을 우선순위를 지정한다. 표기를
입력이나 출력에만 쓰려면 `only parsing`, `only printing`을 사용한다.
표기 선언 왼쪽의 인용 문자열에 넣은 여분 공백도 출력에 반영된다.
`format` 문자열에서 기호를 구분하는 첫 칸 이후의 공백은 그대로 출력에
들어간다. `'/'`는 줄을 나눌 자리, `'//'`는 강제 줄바꿈이다. `'[v  '`와
`']'`는 세로 배치와 들여쓰기 두 칸을 지정한다. 파일을 다시 읽을 수 있게
검사된 선언과 전역 참조를 출력하려면 `--explicit`을 준다.

`Bind Scope calc_scope with Item.`은 인수에서 `Item` 타입이 예상될 때
그 문법으로 읽게 한다. 특정 함수의 첫째·둘째 binder 이름이 `x`와
`y`라면 `Arguments mix x%_calc_scope y%_calc_scope.`로 두 인수의 스코프를 지정한다.
표현식에 직접 붙이는 `%calc`는 스코프를 닫은 뒤에도 쓸 수 있다.

`Disable Notation "_ ⊕ _" (only printing) : calc_scope.`를 실행하면
연산자를 계속 입력할 수 있고 출력에서는 원래 함수 적용을 볼 수 있다.
`Enable Notation "_ ⊕ _" (only printing) : calc_scope.`로 출력을
복구한다. 서로 다른 모듈이 모두 `expression`이라는 custom entry를
선언했을 때에는 `x custom M.expression`으로 어느 모듈의 문법을
확장하는지 지정한다. M 안에서 정의한 표기는 다른 모듈을 불러온
뒤에도 처음 지정한 entry를 따라간다.

표기 안의 생성자 패턴은 LoL이 읽는 Gallina 문법을 따른다. `match`의
분기는 한 층의 생성자 패턴을 받는다. 생성자 안에 다른 생성자 패턴을
넣거나 패턴에 `as` 별칭을 붙이는 문법은 이 릴리스에 없다.
Rocq의 표기 조회 명령 `Print Scope`, `Print Scopes`, `Print Notation`,
`Locate`도 구현되지 않았다.

## Search

`Search _ "twice".`는 현재 보이는 선언 중 이름에 twice가 들어간 것을
출력한다. `Search (f _).`는 해당 적용 모양을 포함하는 선언을 찾는다.
여러 항 패턴과 문자열을 함께 주거나, 제외할 조건 앞에 `-`를 붙여도 된다.
`in M`, `outside M`은 모듈을 기준으로 제한한다. 증명 안에서는 지역 가설도
검색한다. 검색 전후에 목표와 Undo 기록이 같다.

## Section과 Context

```coq
Section Operations.
Context (A : Set) (combine : forall _ : A, forall _ : A, A).
Definition twice (a : A) : A := combine a a.
End Operations.
Check twice.
```

절 안에서는 `A`와 `combine`을 모든 선언에서 쓸 수 있다. `End Operations.`가
끝나면 각 선언은 자신이 의존한 절 변수를 매개변수로 받는다. 절 변수의
이름은 바깥 범위에서 사라진다.

## VS Code

동봉한 확장을 설치하고 이 저장소를 신뢰한 작업공간으로 연다.
`cabal list-bin exe:lol`이 인쇄한 절대경로를 `lordOfLogic.executable`에
설정한다. `example/V1.lol`을 열고 `intros P h.`에 커서를 둔 뒤 명령
팔레트에서 **LoL: Check to Cursor**를 실행하면 가설과 목표가 나타난다.
**LoL: Next Command**는 다음 문장을 실행하고, **LoL: Previous Command**는
한 문장 되돌린다. 앞선 문장을 편집하면 그 문장에 의존한 목표를 새로
계산한다. 설치 절차는 [확장 설명서](../editors/vscode/README.ko.md)에 있다.

## 검사를 다시 돌리기

리눅스에서 `exe:lol`을 빌드하고 Rocq 9.2.0, Python 3, Node를 PATH에 둔 뒤
`bash test/v1.sh`를 실행한다. Rocq 경로를 직접 주려면
`ROCQ=/absolute/path/to/rocq bash test/v1.sh`로 실행한다. 스크립트는
시간과 메모리를 제한한 상태에서 문법과 커널의 대조 및 편집기 통신을
검사한다. 편집기를 쓸 때 필요한 것은 VS Code와 LoL 실행 파일이다.
